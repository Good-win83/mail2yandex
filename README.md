# Mail2Yandex

**Mail2Yandex** — локальный шлюз уведомлений из Яндекс.Почты в Яндекс.Мессенджер. Приложение опрашивает почтовые ящики по IMAP, преобразует письма в текстовые сообщения и отправляет их выбранным сотрудникам или чатам через Bot API Яндекс.Мессенджера.

Проект основан на идее [Mail2Telegram](https://github.com/dYalib/Mail2Telegram). Основной режим работы — **IMAP с несколькими почтовыми ящиками и веб-панелью управления**. При необходимости поддерживается приём почты по SMTP.

## Возможности

- Подключение нескольких ящиков Яндекс 360, включение и отключение опроса из веб-панели.
- Маршрутизация каждого ящика на одного или нескольких адресатов Мессенджера (`login`, `user_id`, `chat_id`).
- Проверка IMAP-подключения, OAuth-токена бота и тестовая отправка каждому получателю.
- Защита от повторной доставки по IMAP UID и получателю с сохранением состояния в SQLite.
- Журнал результатов доставки и диагностика почтовых ящиков без хранения текста писем.
- Административный вход по логину и шестизначному TOTP-коду Google Authenticator.
- Удаление служебных строк из тела уведомления и ограничение длины сообщения.

Схема: **Яндекс.Почта → IMAP SSL/TLS (993) → Mail2Yandex → Bot API → Яндекс.Мессенджер**.

## Требования

- Linux-сервер с Docker Engine и Docker Compose (`docker compose`).
- Доступ к IMAP Яндекса (`imap.yandex.ru:993`) и Bot API Яндекс.Мессенджера по HTTPS.
- Почтовые ящики с разрешённым IMAP и отдельными **паролями приложений**.
- Действующий OAuth-токен бота Яндекс.Мессенджера с возможностью отправлять сообщения нужным получателям.
- Синхронизированное время сервера (NTP) для корректной работы TOTP.

> **Безопасность.** Веб-панель не предназначена для публикации в интернете. Используйте VPN, доверенную локальную сеть и желательно HTTPS через reverse proxy. Логин + TOTP **без дополнительного пароля** не является двухфакторной аутентификацией. По обычному HTTP код TOTP и cookie могут быть перехвачены.

## Установка

### 1. Получить исходный код и создать конфигурацию

```bash
git clone https://github.com/Good-win83/mail2yandex.git
cd mail2yandex
cp .env.example .env
mkdir -p data
cp routes.example.json data/routes.json
```

Если репозиторий уже развёрнут, **не заменяйте существующие** `.env`, `data/routes.json` и каталог `data`: в них находятся действующие настройки, пароли приложений и базы контрольных отметок.

Откройте `.env` и установите основные параметры:

```ini
INPUT_MODE=imap
IMAP_ACCOUNTS_FILE=/data/imap-accounts.json
IMAP_ROUTE_MODE=mailbox
IMAP_POLL_SECONDS=60
IMAP_STATE_DB=/data/imap-state.sqlite
IMAP_STATUS_DB=/data/mailbox-status.sqlite
DELIVERY_HISTORY_DB=/data/delivery-history.sqlite

YANDEX_BOT_TOKEN=УКАЖИТЕ_OAUTH_ТОКЕН_БОТА
YANDEX_CHAT_ID=
YANDEX_LOGIN=
YANDEX_USER_ID=

ROUTES_FILE=/data/routes.json

ADMIN_ENABLED=true
ADMIN_USER=admin
ADMIN_TOTP_SECRET_FILE=/data/admin-totp.secret
ADMIN_SESSION_SECONDS=3600
ADMIN_BIND_IP=127.0.0.1
ADMIN_PORT=8080
ADMIN_COOKIE_SECURE=false

LOG_LEVEL=INFO
```

`ADMIN_BIND_IP` — **адрес интерфейса сервера, на котором Docker публикует порт**. Значение `127.0.0.1` разрешает доступ только с самого сервера (или через SSH-туннель). Для доступа из доверенной LAN укажите LAN-IP сервера. Не устанавливайте `0.0.0.0` без сетевых ограничений. Значение `ADMIN_COOKIE_SECURE=true` используйте **только при доступе браузера по HTTPS**.

В режиме нескольких ящиков адреса и пароли почты добавляются **через веб-панель**; значения `IMAP_USER` и `IMAP_APP_PASSWORD` из `.env` при заданном `IMAP_ACCOUNTS_FILE` не используются.

### 2. Настроить Google Authenticator

TOTP-секрет создаётся локально скриптом `scripts/setup_totp.py`. Для генерации QR-кода нужен Python с `venv` и временная библиотека `qrcode[pil]` — **только на хосте**, не в контейнере.

На Ubuntu/Debian при отсутствии `venv` установите пакет для своей версии Python (например, `python3-venv` или `python3.10-venv`).

```bash
python3 -m venv /tmp/mail2yandex-totp-venv
/tmp/mail2yandex-totp-venv/bin/python -m pip install 'qrcode[pil]'

/tmp/mail2yandex-totp-venv/bin/python scripts/setup_totp.py \
  --file data/admin-totp.secret \
  --qr admin-totp-setup.png \
  --user admin
```

Откройте `admin-totp-setup.png` на доверенном устройстве и добавьте его в Google Authenticator. Если `data/admin-totp.secret` уже существует, скрипт **использует имеющийся секрет**, не меняя коды.

Если скрипт не может прочитать существующий секрет из-за прав, временно предоставьте доступ владельцу файла для генерации QR, а затем верните права контейнеру. **Не удаляйте секрет для решения ошибки доступа.**

После привязки назначьте владельца файлов процессу контейнера (UID 65534):

```bash
sudo chown -R 65534:65534 data
sudo chmod 600 data/admin-totp.secret
sudo chmod 600 data/routes.json
```

После **проверки успешного входа** удалите QR и временное окружение:

```bash
rm -f admin-totp-setup.png
rm -rf /tmp/mail2yandex-totp-venv
```

**Не удаляйте** `data/admin-totp.secret`: этот файл необходим для последующих входов. Храните его защищённую резервную копию; QR и секрет нельзя отправлять в GitHub или общедоступные сервисы.

### 3. Запустить контейнер

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 mail2yandex
```

При необходимости открыть панель с другого компьютера измените `ADMIN_BIND_IP` на LAN-IP сервера и повторно создайте контейнер:

```bash
docker compose up -d --force-recreate
```

Страница входа: `http://IP_СЕРВЕРА:8080/login` (для рабочего использования предпочтителен HTTPS). Введите `ADMIN_USER` и текущий шестизначный код Google Authenticator. Отдельный пароль веб-панели не используется.

## Настройка в веб-панели

### Почтовые ящики

В разделе **«Почтовые ящики Яндекс 360»** добавьте полный адрес ящика и пароль приложения Яндекс.Почты. Приложение подключается к `imap.yandex.ru:993` по TLS и читает папку `INBOX`.

Нажмите **«Сохранить ящик»**, затем **«Проверить»**. Проверка устанавливает соединение, выполняет вход и открывает INBOX только для чтения: письма не пересылаются и не помечаются прочитанными.

У каждого ящика есть признак **«Включён»** и показатели последней попытки, последнего успешного опроса, количества обработанных писем и доставок. Время в диагностике — **UTC**.

Пароль приложения сохраняется в локальном `data/imap-accounts.json` с ограниченными правами. После сохранения пароль не отображается в браузере. Защищайте каталог `data` и резервные копии: сам файл не зашифрован.

### Получатели и маршруты

В разделе **«Маршруты — несколько получателей»** свяжите полный адрес каждого почтового ящика с одним или несколькими адресатами Мессенджера. Те же маршруты хранятся в `data/routes.json`:

```json
{
  "routes": {
    "mailbox@example.org": [
      {"login": "employee1@example.org"},
      {"login": "employee2@example.org"}
    ],
    "alerts@example.org": [
      {"chat_id": "0/0/example-chat"}
    ]
  }
}
```

Для личных сообщений сотрудникам организации указывайте корпоративный адрес в поле `login`. Бот может доставлять личные сообщения только разрешённым ему пользователям в пределах поддерживаемой организационной области и с учётом настроек приватности адресата.

Значение `IMAP_ROUTE_MODE=mailbox` выбирает получателей по **адресу подключённого почтового ящика**. Дополнительный режим `headers` маршрутизирует по почтовым заголовкам `To`, `Cc` и другим; он не рекомендуется для недоверенных входящих писем, потому что заголовки могут быть подделаны.

### Проверка доставки

Рекомендуемый порядок:

1. **«Проверить»** напротив почтового ящика — доступность IMAP.
2. **«Проверить OAuth-токен»** в диагностике бота — действительность токена.
3. **«Тест»** напротив каждого получателя — реальная тестовая отправка в Мессенджер.
4. Отправить **новое непрочитанное письмо** на подключённый ящик, затем посмотреть **«Журнал доставки по получателям»**.

## Формат уведомления

В Мессенджер отправляются заголовок «📧 Новое письмо», **тема** и **текст письма**. Отдельные поля `От:` и `Кому:` не добавляются. Из текста удаляются известные служебные фразы:

- «При ответе на данное письмо, пожалуйста, не изменяйте тему письма!»
- «Письмо сгенерировано автоматически.»

Фильтр учитывает распространённые пробелы, невидимые символы и переносы текста. Содержимое прочих строк сохраняется. HTML преобразуется в обычный текст; **вложения не пересылаются**. Длина уведомления ограничивается параметром `MESSAGE_MAX_CHARS` (обычно 5500, максимум 6000 символов).

## Как обрабатываются письма

- Каждый включённый ящик опрашивается с интервалом `IMAP_POLL_SECONDS` (по умолчанию 60 секунд).
- Обрабатываются письма с флагом **UNSEEN**. Уже прочитанные письма не выбираются для доставки.
- Успешная отправка отдельно каждому получателю фиксируется в `IMAP_STATE_DB`; при повторной попытке уже обслуженный адресат обычно не получает копию.
- Когда письмо успешно доставлено всем получателям, оно помечается прочитанным при `IMAP_MARK_SEEN=true`. При ошибке доставки письмо остаётся непрочитанным для последующего опроса.
- Не удаляйте SQLite-файлы состояния и не запускайте параллельно два экземпляра сборщика на одном почтовом ящике: это может привести к повторам.
- История отправок (`DELIVERY_HISTORY_DB`) содержит служебные сведения о доставке, но не текст писем.

## Обслуживание

**Обновление** (перед началом сохраните резервную копию `.env` и `data`):

```bash
git pull --ff-only origin main
docker compose up -d --build --force-recreate
docker compose logs --tail=80 mail2yandex
```

**Проверка состояния и журналов:**

```bash
docker compose ps
docker compose logs -f --tail=100 mail2yandex
```

**Остановка:**

```bash
docker compose down
```

`docker compose down` не предназначен для удаления `./data`; **не удаляйте этот каталог**, если хотите сохранить аккаунты, маршруты, TOTP и историю доставки.

## Устранение неполадок

| Симптом | Что проверить |
|---|---|
| Веб-панель не открывается | `docker compose ps`, `ADMIN_BIND_IP`, `ADMIN_PORT`, сетевые правила и `docker compose port mail2yandex 8080`. |
| Не удаётся войти по TOTP | Синхронизацию времени, `ADMIN_USER`, наличие `data/admin-totp.secret` и права чтения UID 65534. |
| `ROUTES_FILE is required` | Наличие `ROUTES_FILE=/data/routes.json` в `.env` и доступность `data/routes.json`. |
| Ящик не опрашивается | Добавлен ли он в веб-панель, включён ли, доступен ли IMAP, правильно ли указан пароль приложения. В многоящичном режиме `IMAP_USER` не используется. |
| Проверка ящика не проходит | Сообщение проверки и колонку последней ошибки; этапы `connect`, `login`, `select` помогают отличить сеть от учётных данных и выбора папки. |
| Письмо не пришло в Мессенджер | Статус получателя, маршрут ящика, тест Bot API, флаг UNSEEN, журнал доставки, лимиты API и права бота. |
| Сообщение пришло повторно | Сохранность `IMAP_STATE_DB`, отсутствие второго опрашивающего экземпляра, постоянство каталога `data`. |
| `Permission denied` для файлов в `data` | Владелец и права каталога/файлов; контейнер выполняется от UID 65534. |

**Никогда не прикладывайте к публичным сообщениям** полный `.env`, `imap-accounts.json`, TOTP-секрет, QR-код, токен бота или пароли приложений.

## Основные настройки

| Переменная | Назначение |
|---|---|
| `INPUT_MODE` | `imap` (основной), `smtp` или `both` |
| `IMAP_ACCOUNTS_FILE` | JSON-файл подключённых ящиков |
| `IMAP_ROUTE_MODE` | `mailbox` (рекомендуется) или `headers` |
| `IMAP_POLL_SECONDS` | Интервал опроса, секунды |
| `IMAP_BATCH_SIZE` / `IMAP_MAX_BYTES` | Ограничения количества и размера писем |
| `IMAP_MARK_SEEN` | Помечать письмо прочитанным после успешной доставки |
| `IMAP_STATE_DB` | SQLite-контроль повторной доставки |
| `IMAP_STATUS_DB` | SQLite-диагностика ящиков |
| `DELIVERY_HISTORY_DB` | SQLite-журнал получателей |
| `YANDEX_BOT_TOKEN` | OAuth-токен бота |
| `ROUTES_FILE` | JSON-файл маршрутов |
| `ADMIN_ENABLED` / `ADMIN_USER` | Включение панели и имя пользователя |
| `ADMIN_TOTP_SECRET_FILE` | Секрет Google Authenticator |
| `ADMIN_BIND_IP` / `ADMIN_PORT` | Сетевой адрес и порт панели на сервере |
| `ADMIN_COOKIE_SECURE` | Защищённый cookie при HTTPS |
| `AUDIT_DB` | SQLite-журнал событий |
| `MESSAGE_MAX_CHARS` | Максимальная длина текста уведомления |

Дополнительные переменные и их значения по умолчанию приведены в [`.env.example`](.env.example).
